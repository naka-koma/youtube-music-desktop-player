# 描画とタイトルスクロール

通常表示と全画面表示は同じスクロール部品と描画アダプターを使う。Smooth は約30fps相当の設定を維持する。

## 部品の責任

| ファイル（`@Resources/` 基準） | 責任 |
| --- | --- |
| `Components/Marquee.lua` | 待機、移動、末尾での停止、先頭へのリセットを計算する。Rainmeter、時計、フォントに依存しない |
| `Components/Renderer.lua` | Rainmeterへの描画操作をまとめる。座標の丸め、同じピクセルへの移動の省略、再描画要求を担当する |
| `TitleMarquee.lua` | 画面側との接続。曲名変更と実際の文字幅を検出し、経過秒数と表示幅をスクロール部品へ渡す |
| `Fullscreen.lua` | 全画面の配置・入力・再生情報の差分判定。描画操作は `Renderer` に渡す |
| `Performance.Profiles/*.inc` | モードごとの描画間隔、情報取得周期、スクロールの有効・無効を定義する |

部品はファクトリー関数を返し、呼び出し側ごとに状態を持つ。通常表示と全画面のスクロール位置や描画キャッシュは共有しない。RainmeterのLuaでは `require` を使わず、`Initialize` / `Start` で `dofile` して生成する。

## 文字の変更と移動を分ける

曲名が変わった時だけ `Renderer:updateMeter` で文字のレイアウトを更新する。新しい幅を取得できる次の更新まで待ち、スクロール位置を先頭に戻す。表示幅が変わった場合も先頭に戻す。

スクロール中は `Marquee:step` が位置を計算し、`Renderer:move` が描画済みの文字を移動する。速度と待機時間はフレーム数ではなく経過秒数で扱う。短いタイトルと Power Saver は先頭で静止する。

`Renderer:move` は `!MoveMeter` を使う。Luaの `SetX` だけに置き換えてはいけない。全メーターが `UpdateDivider=-1` の場合、座標の計算は進んでも再描画されないためである。通常表示は他のメーターの更新で再描画されるので、この不具合を見落としやすい。

## 描画APIの使い分け

| 操作 | メソッド | 注意点 |
| --- | --- | --- |
| 既存レイアウトの移動 | `move(name, x, y)` | 再描画も要求する。同じピクセルへの移動は省略する |
| 文字などのレイアウト更新 | `updateMeter(name)` | 内容が変わった時に使う。移動だけのフレームでは呼ばない |
| 関連する部品の更新 | `updateGroup(name)` | 背景なら `FSArtwork` など、必要な範囲に限定する |
| テキスト値のデコード | `updateMeasure(name)` | 必要に応じて、その後に対象メーターを更新する |
| 変数・設定値の変更 | `setVariable` / `setOption` | これだけで画面が変わるとは限らない。変更後に対象メーターかグループを更新する |
| 表示・非表示 | `showMeter` / `showGroup` | 表示範囲だけを変更する |

再生位置や時刻の更新で `FSContent` 全体を更新しない。背景、タイトル、アーティスト、時刻、操作ボタンは、それぞれ内容が変わった時だけ更新する。`Renderer` は毎フレームの `!Redraw` を追加しない。

## 確認すること

- `Scripts/tests/components.lua`：純粋なスクロール計算と描画要求の契約。
- `Scripts/tests/rendering.lua`：モード設定と、画面につないだスクロール動作。
- `Scripts/tests/fullscreen.lua`：全画面の部分更新、背景の到着、シーク後の閉じる判定。

各テストはLua 5.1で `dofile('.../Scripts/tests/components.lua')('.../repo')` のように実行できる。RainmeterのLuaから呼び出すこともできる。

実機では通常表示と全画面の両方で、長短のタイトル、曲名変更、モード切り替えを確認する。Luaの更新回数を描画fpsとして報告しない。スクロール中は、位置変更に伴う再描画要求も確認する。
